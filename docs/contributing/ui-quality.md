# UI 改动完成标准

组件、入口接通、提交数量与局部测试通过不等于整页完成。整页迁移应满足以下条件：

1. 对照原页字段、入口、默认值、权限、平台分支和错误/空态，不能因改设计静默丢功能；未决定的产品问题保留原行为并记录。
2. 基础与业务布局使用独立组件包，App 保留真实数据、资金口径、身份、权限、平台服务与生命周期；同一组件同步 Flutter 目录、HTML 设计源和覆盖契约。
3. 验证窄屏、长短屏、明暗、字体放大、长文、多标签、外币、缺率与自定义图像。普通交易行优先两行，复杂最多三行，完整字段仍可访问。
4. 运行改动所需单元/Widget 检查。使用同一个有归属的隔离环境完成真实读取、写入、取消、返回与正常重启；清楚区分本轮原生动作、历史证据和未执行项。
5. 更新 App 前备份当前数据库、偏好与附件；核验实际 APK 包名、Provider和签名。禁止将 Flutter integration test 指向用户安装包，禁止卸载/清空来解决验收失败。
6. 报告固定源码、产物、实际数据规模和独立证据。原始日志、真实库、签名、密钥和备份只保存在 `.docs` 或私有 run；公开发布说明只描述已交付行为和用户应知限制。

设计资源在 [独立设计仓](https://github.com/TNT-Likely/BeeCount-Design)，App 只保留构建与回归所需最小契约。临时进度和迁移问答在本机 `.docs/development`，长期产品行为与技术兼容约定应整理到 `docs/decisions` 和 `docs/architecture`。
