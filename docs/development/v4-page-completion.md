## 完成标准

一个页面只有同时满足以下条件，才标为“完整完成”。换用新主题、接入组件、页面能打开、编译通过均属于迁移过程。

1. **设计对齐**：明确对应的 HTML 路由和版本，以相同屏幕尺寸、字体缩放、主题与数据状态对照。核对页面结构、各区尺寸、间距、圆角、字号、图标、语义色以及弹窗。缺失的场景先补入设计稿。平台状态栏及系统安全区按实际设备适配。
2. **功能不减**：与备份原代码逐项核对入口、字段、筛选、操作、异常与空态。保留原数据口径、历史兼容、共享权限和导航；需要产品决定的差异进入待确认文档，不能自行删功能。
3. **组件化**：基础交互放 `beecount_ui`，可复用财务界面放 `beecount_business_ui`，真实数据、权限、缓存和 Repository 请求留在 App binding。页面组合组件，不以搬走整个旧页面作为组件化完成的证据。
4. **相关回归**：按风险执行单元/widget 测试，包括保存/取消、防重复、历史字段、边界和必要的布局断言。关键布局与已冻结的 HTML 尺寸比较，不以新实现与自身比较。
5. **隔离设备验收**：复用同一个 QA 包与数据，按 isolated-app-cloud-qa 技能操作实际生产 UI。写入后独立核对本地对象与字段，记录失败、未执行及外部依赖；正常入口重启后检查持久化。每页留下对应源码和产物版本的证据。
