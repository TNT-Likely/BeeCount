# Beta2 首页启动交接与补充验收数据

## 启动回归与修复

Beta1 启动阶段已读取前 20 条完整账单，但只存入旧的行缓存；新版首页没有消费这份缓存，进入页面后又异步查询一次，因而先显示加载状态。直接恢复旧缓存也不安全：旧缓存没有账本范围、完整日汇总和总笔数，而且读取发生在周期账单生成之前。

Beta2 改为以下顺序：

1. 先完成欢迎流程检查及已保存账本、主题和显示偏好的恢复。
2. 完成原有周期账单生成与后处理，再查询当前账本的首屏。
3. 首屏快照包含最多 20 条账单、分类/账户/标签/附件数量、原有折算信息，以及相关日期的完整汇总和整个账本的真实笔数。查询失败时留在启动页，提供重试。
4. 用绑定 Repository 实例和账本 ID 的一次性快照进入首页；不再丢弃结果后重复查询。若锁屏等待期间数据变化，重新准备首屏后进入。
5. 首个可用画面绘制之后再订阅完整账本。沿用已有完整关系数据准备、代际检查和稳定列表键，后台结果完整后再接替首屏。

这不是将 20 条账单冒充完整账本。正常切换账本、滚动、跳转和后台全量更新仍走原有首页链路；一次性快照不会在之后导航时重新回放。空账本使用真实空快照，不为等待后台空流额外显示转圈。

## 验证范围

新增测试使用真实 LocalRepository、内存 SQLite 和实际 Flutter 启动/首页组件，覆盖：

- 首屏就绪前不进入首页；首个首页画面已有 20 条完整关系、42 笔真实总数和整日金额，且不重复查询首屏。
- 等待期间发生数据修改时，旧快照失效，重新准备后才显示。
- 周期账单先生成，首屏笔数和日汇总包含本次新增记录。
- 已保存账本优先于临时默认账本。
- 首屏读取失败可重试，不进入假空首页。
- 空账本立即呈现真实空状态；一次性交接及账本范围检查。

同时复跑首页全量接替、旧请求乱序、旧缓存隔离、元数据失败重试、启动页布局及原有首页交互测试。以上是本地回归证据，不能代替下一版 APK 在保留的 15,000 条真机环境中的启动验收；本次未操作设备，也未修改保留的数据。

## 补充测试数据方案（待统一执行）

原大数据集擅长覆盖大量账单、外币和多标签，但账户类型、标签颜色、自定义图片覆盖不足。下一次仍在同一隔离环境，通过真实 Repository 或产品入口补齐，使用独立测试前缀标识，不清空或覆盖旧账本与原记录。

| 维度 | 建议用例 | 主要检查位置 |
| --- | --- | --- |
| 流水账户 | 现金、银行卡、信用卡、支付宝、微信、其他；信用卡欠款/溢缴款、带与不带额度；同币种转账及外币账户 | 资产页、账户选择、账户详情、转账 |
| 估值账户 | 房产、车辆、投资、保险、社保公积金、贷款；零值、正值和产品允许的负债情况 | 资产分类、总资产/净资产、估值编辑 |
| 标签 | 多种真实保存的标签颜色；同一账单 1/2/5 个标签；长名称、中英混合，与外币折算、附件、不计收支/预算组合 | 首页两行优先/最多三行、选择弹窗、标签详情 |
| 自定义分类图片 | 一级/二级分类分别使用透明 PNG 和方图；同时保留内置图标；验证缺失文件占位 | 首页、分类管理、二级展开、更多分类、分类详情、记账页 |
| 持久性 | 新数据重启后保留；切账本和改变主题/隐私显示后仍完整；原测试记录逐项守卫 | 正常冷启动、设置返回和数据核对 |

账户类型仅使用现有产品支持的类型，不增加业务规则。图片必须存入真实受管文件并建立分类引用；不能仅在数据库写一条不存在的路径就宣称图片场景通过。准备完成后再补实际 UI 截图和结果，本方案本身不代表已造数或已通过真机验收。
