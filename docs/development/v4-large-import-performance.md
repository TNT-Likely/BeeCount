# V4：15000 笔导入与首页首屏验收

本任务复用当前 Android 隔离 App 和已保留数据，仅增加一个独立压力账本。生成数据、离线解析和 Widget 检查不代表真机性能通过；原生结果、确切产物、计时和数据守卫另保存在本地独立报告中。

## 数据与入口

`tool/v4/generate_large_import_fixture.py` 生成 UTF-8 BOM CSV、逐条独立 JSONL oracle 和 SHA256 manifest。默认 15000 笔、2% 超千字备注；生成目录必须位于忽略的私有目录或明确指定的仓库外目录，不覆盖已有文件。主数据约 5.94 MB；之前 20% 长备注的约 16 MB 候选保留作可选极端文件，本轮只真实导入主文件一次。

数据包含 10500 支出、3000 收入、1500 符合原规则的同币种转账，八种币种（含零位及三位小数币种），8471 笔二级分类、0/1/2/6/12 个标签、标签输入重复去重、588 笔无账户、149 笔零金额、最小非零/大金额、负号与千分位输入、逗号及双引号、Unicode、跨年月和闰日。前 48 笔集中在当天，包含外币、长备注、多个标签、转账、大额和零值，便于直接观察首屏。

真正写入必须经原 App 的文件选择、字段映射、分类预览、账户币种预览和最终确认。不能用直接 SQL 或 Repository 循环写入 15000 笔，代替“导入已测”。分类/账户/标签使用专用前缀；新增对象和笔数以实际新账本 ID 为准，不硬编码原环境必须仍为 72 笔。用户在验收期间新增的内容也属于需要保护的当前基线。

可传 `--attachment-names-json <私有文件>`，让前 16 笔引用已核验的本次 QA 现存附件 basename。CSV 的附件列只创建元数据，不导入二进制；未提供该参数时 manifest 的附件数为 0，不能宣称该 CSV 已测试附件图片导入。若采用该选项，必须先实际读取 QA 文件并核 SHA，后续核引用和预览，原文件继续保留。

CSV 不支持历史 `nativeAmount` 快照、统计/预算排除标记、标签颜色或分类自定义图片；它们不能凭文件字段伪造。导入折算按原服务的实际有效汇率生成，缺汇率时原有 1:1 待补边界另列。原 `CsvParser` 不支持带引号字段中的真实换行，因此主数据使用单行长备注；内容级重复文件去重也未实现，不能重复导入同一文件后宣称自动去重。

## 先确定的计时目标

以下为本次真机验收目标，实测未达到时保留失败并定位，不能事后下调门槛把失败写成通过。

| 阶段 | 起止与目标 |
| --- | --- |
| 文件读取与解析 | 系统文件选择完成后到映射预览可用；单独记录，不含用户找文件和手动确认时间 |
| 导入入库 | 账户币种预览最终确认到成功完成；主 15000 笔本地目标不超过 30 秒，成功 15000、失败 0、跳过 0 |
| 首页完整首帧 | 已运行 App 进入15000笔账本，到首屏真实交易及全部元信息可见；与官方3.9.0同数据/同模式对照，确认无性能下降。用户已取消切账本固定2秒门槛 |
| 冷启动 | 正常 MAIN 启动单列统计，包含原初始化/预加载；不与热态账本切换混算 |
| 首屏稳定 | 完整首帧后至少连续 2 秒，数据未变化时行高、可见标签/附件/账户、原币/折算与日期汇总不再二次补入或跳动 |

同时记录 APK hash、提交、设备/运行模式、数据规模、测量起止、误差和采用的截图/录屏/原生日志。Debug 真机结果不外推为 Release 或其他设备承诺。保存进度事件和既有 `TxImport` 分批/总体 Stopwatch，剔除人为确认等待；不能只报程序进程存活或 `am start -W` 返回时间。

## 2026-10-26 验收口径调整

用户明确：切账本可以忽略固定耗时，只要相较原来没有下降；重点是15000笔账本首屏流畅、完整显示后不闪烁/补字段。R119/R120按旧2秒目标得到的失败报告原样保留，不回改结果。后续将普通首个列表、完整字段就绪、冷启、暖返回和滚动分列，使用官方3.9.0同一合成数据副本/同机同AOT模式对照，不把v4旧候选称为原版。表中的连续2秒仅是稳定性观察窗口。

## 首屏链路修正

旧列表先绘制基本行，再由标签和附件的两个异步读取分别 `setState`，会让新账本或非启动缓存范围的行随后增高。现在使用完整元数据快照：

- `transaction_list_metadata.dart` 将 ID 去重并限制为每批 400、最多三个批次在途；标签与附件都完成后才返回整个快照。读取失败显式重试，不把未知值当空关系。
- `TransactionList` 同一账本刷新时保持上一份完整快照；切换账本清旧显示，generation 检查拒绝迟到的旧请求。新交易集合和全部关系在一次提交中发布，整日汇总、跳月和列表数据仍来自完整原集合，没有引入只看 40 笔的伪分页。
- Home 用 `sourceReady` 明确区分启动时前 20 笔缓存和真实完整 Stream。有限缓存只用于已有元数据，不能先绘制部分日合计再变成整本合计。
- 日期分组和扁平索引按已发布的完整列表缓存，隐私、主题或其他无关 rebuild 不再重复分组/排序整个 15000 笔集合。

## 同步与数据保护

原 `Ledgers` 没有逐账本禁止同步字段。Cloud `SyncEngine` 始终自动同步，`auto_sync=false` 不能禁止它；仅创建新账本不意味着本地隔离。

本轮纯本地压力阶段通过原云服务页面的“离线模式 → 本地存储”切换，先私密备份配置和当前会话。该原流程会登出旧云会话、关闭旧 runtime，再使用 `LocalOnlySyncService`；服务配置保留。完成后保留 QA 为本地供用户压力验收，原云配置和账号继续私密保留。切回 Cloud 时，专用账户/分类/标签属于 user-global 数据可能被同步，切到压力账本又会自动上推 15000 笔，不能未经新的明确范围把该动作当作“恢复无影响”。

导入前备份当前 QA 数据库、偏好、附件、自定义图片和已拥有的公有导出；逐行核对所有原业务记录与文件字节不变。允许的新增限于压力账本及其有归属的交易/分类/账户/标签/关系和必要变更队列。不能清空原环境、回灌旧快照、重建 App，或影响用户原应用包。关联 PR 未合并且用户仍在验收时，环境和备份保持。

## 结果边界

当前源码和离线准备不等于已完成原生导入。最终报告需分别写：生成/实际 Dart 解析、真实导入结果及总耗时、数据库逐条关系对照、首屏与后续滚动、2 秒稳定窗口、热态/冷态差异、原数据与原附件保护，以及未执行项。旧失败材料继续保留，后续成功不能覆盖原候选报告。
