# 大账本导入与首屏性能

压力场景使用 15000 笔合成数据，覆盖收支、同币种转账、多币种、二级分类、不同标签数、无账户、零值、大额、长备注、Unicode、跨年月和闰日。账户类型、彩色标签与自定义分类图片需要经原 App 流程补齐；CSV 不支持的字段不能凭虚构列宣称覆盖。

导入必须经原文件选择、字段映射、分类/账户币种预览和确认，不以直接 SQL 或 Repository 循环代替。生成器为 `tool/v4/generate_large_import_fixture.py`，输出放忽略目录，保留 JSONL oracle 与 SHA256。不要重复导入同一文件而把账本扩大到 30000 笔。

| 测量 | 口径 |
| --- | --- |
| 解析 | 系统选文件完成到映射预览可用，排除用户找文件与确认等待 |
| 入库 | 最终确认到成功完成；15000 笔目标 30 秒内、失败 0、跳过 0 |
| 首页首帧 | 首批20笔交易与其账户、标签、附件、原币/折算和日期汇总一起就绪后进入；后台静默加载完整集合 |
| 首屏稳定 | 完整首帧后连续2秒，数据不变时无字段补入、行高跳动或全屏 loading |
| 冷启与切账本 | 分别记录；与官方3.9.0同机、同数据和同AOT模式对比，切账本不另设固定2秒门槛 |

元数据读取按ID去重、每批400、最多3批在途；全部关系完成后原子发布完整快照。请求generation拒绝过期结果，同一账本刷新保持上一份完整快照。首批20条缓存不能把局部日合计冒充完整汇总；真实集合和完整关系静默就绪后更新。日期分组与扁平索引按已发布集合缓存，主题或隐私 rebuild 不重复排序15000笔。

每份结果需带源码、APK hash、设备与模式、数据规模、计时起止与误差、稳定窗口、全表/原附件保护和未执行项。Debug 计时不能外推 Release；`am start -W` 或进程存活不能代表首屏可用。

原生操作只复用已验证归属的隔离 App。安装前私密备份数据库、偏好、附件与自定义图片，核包名、Provider、签名、UID与firstInstall。纯本地压力测试通过原离线模式入口隔离；切回云可能上传全局资源和整本交易，需要符合当轮授权范围。原始计时、失败和升级证据保存在 `.docs`，后续成功不能覆盖失败记录。
