# 账户详情精修交互稿

状态：**用户已确认；已实现 Flutter 组件、真实查询与页面，并同步主 demo。原生验收由主任务统一执行。**

预览：`http://127.0.0.1:8374/boards/account-detail-refinement.html`

对应用户偏好的旧稿结构：彩色账户图标与名称 / 类型币种 → 大字余额 → 账户类型、净资产、关联账本三列 → 转账与记一笔 → 月 / 年 / 全部及年月 → 账户收支 → 余额趋势 → 账户流水。

## 本稿设计

- 账户图标直接嵌入项目原 SVG，保留微信绿、银行卡和信用卡等原有颜色，不重绘或一律变灰。
- 余额是“当前余额”，**不随下方年月筛选变化**。外币原币余额保持完整，次行以靠右金额展示参考 CNY 折算；点按解释汇率用途。
- 三列摘要分别展示账户类型、是否计入净资产、已有流水关联账本数量。关联账本可查看，不新增按账本限制账户使用的规则。
- 转账和记一笔并排；信用卡将转账改为还款，预选其为转入账户。转账仍只允许同币种账户。没有其他同币种账户时，保留解释及新增账户入口。
- 周期控件与分类详情新稿一致：32px 视觉轨道、44px 触控区域，日期滚轮从底部弹出。默认月视角；全部、年、月筛选影响下方统计、趋势和流水。
- 账户收支保留收入、支出、净流入三列。延续原账户统计口径：收入含转入、支出含转出，不计收支的记录排除；余额计算仍包括实际资金变化。外币账户在卡片标题统一注明币种，三列不反复堆叠 `US$`。
- 现有分类统计没有丢掉：从收支卡右上角“分类占比”打开，支持支出 / 收入及分类选择。
- 余额历史曲线基于本页合成交易与初始余额逐笔计算，点击节点查看对应时点。没有历史数据时显示空态，不伪造曲线。

## 特殊账户与已有功能

| 场景 | 本稿处理 |
| --- | --- |
| 微信 / 银行卡 | 正常余额、转账、记账、收支、趋势、流水；银行卡保留银行、尾号、备注 |
| 信用卡欠款 | 保留欠款、总额度、估算可用额度、额度进度、账单日、还款日、还款入口 |
| 信用卡溢缴款 | 主金额标记“溢缴款”，不误写为欠款 |
| 外币账户 | 原币余额、参考折算说明、同币种转账；金额与单据币种保持原语义 |
| 投资 / 贷款 | 仅更新当前估值 / 欠款；保留最近更新时间，不提供日常记账或转账，不假造估值历史曲线 |
| 空账户 | 零余额与无流水空态，仍可记账 |
| 无同币种对手 | 说明原因并提供添加入口，不能直接创建跨币种转账 |
| 隐藏账户 | 隐藏确认、历史记录与余额保留、不能新增记账 / 转账，提供恢复；原应用默认账户清理与周期提醒规则不在视觉改稿中改变 |
| 删除账户 | 复用原后果提示：有关联交易时清空其账户信息，交易本身保留。只在本页模拟删除，可重置恢复，不写真实数据 |

右上角菜单保留编辑、搜索流水、关联账本、隐藏 / 恢复、删除。编辑弹层演示名称、净资产状态与备注；完整类型、银行 / 信用卡字段、余额调整及原账户编辑校验继续沿用已有完整页面，本稿不另定义业务规则。

流水可搜索备注 / 分类 / 账本，可按全部、收入与转入、支出与转出筛选及排序；支持全部展开、账单详情。原币、方向、账本标签、时间、附件与标签保留。预览中的记账、转账、估值、隐藏和删除均只改变内存中的合成数据。

## 已实现映射（2026-10-26）

- `BeeAccountSummaryCard`、`BeeAccountCashflowCard`、`BeeBalanceHistoryCard` 是受控业务组件；数据查询保留在 App 和 Repository。
- 原有 `getAccountDailyBalances` 计算真实逐日余额，包含期初、区间前交易和转账，排除加入他人的共享账本。新范围分页、排序与搜索在 SQL 先过滤，汇总与历史不从第一页推算。
- 统计遵守原有账户口径；原币/历史快照不改写。月/年/全部仅过滤下面的统计和流水，当前余额不随日期变化。
- 现有模型**没有独立的“计入净资产”开关**；实现如实显示“已计入”，隐藏账户也计入。保留现有规则，不新增数据库字段或伪开关。
- 信用卡还款目标、估值/贷款更新、账户隐藏时默认选择清理和周期引用提示、删除时交易账户清空规则继续沿用。
- Flutter 基础/业务验收页已补齐相关组件。浏览器、SQLite、Widget 的报告留在 `.docs`；尚不表示原生真机验收通过。
