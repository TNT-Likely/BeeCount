# BeeCount 色彩层次提案

日期：2026-10-26。状态：**独立候选方案，待用户确认，尚未应用到 App。**

预览：[本地交互页面](http://127.0.0.1:8374/boards/color-balance-review.html)。

这次选取 6 个最能体现灰白问题的页面，直接在当前 `prototype/demo.html` 上叠加独立配色层。手机内使用现有组件和真实原型交互，所有账本、金额、分类图片与任务状态都来自原型的合成数据。没有调用数据库、Cloud 或系统账户。

## 页面选择与方案

| 页面 | 现稿依据与选择原因 | 建议用色 |
| --- | --- | --- |
| 明细首页 | 高频浏览；汇总卡与账单列表同为白底，分类图标大多为中性色 | 汇总卡混入 5% 主题色；账单分类图标用稳定家族色；保留 C3 布局和收支金额语义。默认带“蜜蜂记账”品牌，可在右侧切换无品牌状态 |
| 资产账户 | `asset-overview.css` 对账户图标明确设置 `grayscale(1)`、`opacity:.78` | 恢复原 SVG 颜色与完整不透明度；图标加极淡对应底；仅净资产汇总卡轻染主题色，趋势 / 构成继续单主题色 |
| 分类管理 | `category_management_bindings.dart` 的 `RecordingCategoryIcon` 使用 `onSurface`；HTML 对应行以中性底呈现 | 一级 / 二级 / 首页使用相同家族色；展开组轻底衔接；自定义图片不套色、不更换、不修改裁切 |
| 预算管理 | 同时存在对象类别和预算阈值两套含义，适合验证配色边界 | 总预算卡轻染主题色；类别图标使用家族色；进度条、百分比、超预算金额沿用当前阈值语义 |
| 我的 | F / A 布局已确认，头像和紧凑余额条无需重新设计；菜单大多同色 | 余额卡极淡主题底；云服务湖蓝、智能与自动化浅紫、数据管理湖蓝；保留单层头像、负余额和同步错误色 |
| 数据管理 | 账单、分类、配置、附件四组结构完整，但图标难以扫读 | 账单湖蓝、分类浅紫、配置麦穗、附件薄荷；仅首组轻染湖蓝；进度 / 成功 / 部分失败保持原语义 |

## 色彩职责

主题色使用现有选项：蜜蜂黄 `#f8c91c` 与青莲紫 `#7e57c2`。主题只负责选中、主要操作和极淡汇总背景；更换主题不改变对象家族色。

| 家族 | 浅色图标 / 浅色底 | 深色图标 / 深色底 | 用途 |
| --- | --- | --- | --- |
| 麦穗 | `#936b25` / `#fbf2de` | `#dfbb78` / `#393223` | 餐饮、居家、现金、配置与存储 |
| 湖蓝 | `#406f9c` / `#eaf2fa` | `#9abce0` / `#263442` | 交通、云服务、银行卡、数据导入导出 |
| 浅紫 | `#866197` / `#f2edf7` | `#c6a8dc` / `#372d41` | 购物、数码、智能、自动化、分类与标签 |
| 薄荷 | `#377b70` / `#eaf5ef` | `#8ec9b9` / `#253a33` | 文教、运动、附件、微信 |
| 玫瑰 | `#a15f73` / `#faedf0` | `#dda5b4` / `#3c2c33` | 医疗、人情、宠物等对象图标 |

这些是识别对象的低饱和色，不表示财务结果或操作状态。金额、标签、预算阈值、错误和同步状态没有改写；自定义分类图片优先于家族色。数据同步状态图标也不套用装饰色，避免让“云功能蓝色”被误解为“同步成功”。

每页保留大部分白色 / 原深色表面，只给一张主要汇总卡轻底，不增加大 Header、不铺满浓色、不加入渐变卡或新的大插画。

## 交互和文件边界

- 左侧选择六页，右侧说明为何选择和颜色用途；只展示优化后页面，没有旧 / 新左右对比。
- 顶部切换蜜蜂黄 / 青莲紫、浅色 / 深色、398×844 / 375×667 / 320×568。URL 保存页面、主题、模式与尺寸，可直接分享指定组合。
- “标记用色位置”显示虚线轮廓，方便辨别本次颜色改动；默认关闭。
- 手机内继续使用现有原型交互。快捷操作可打开账本弹窗、隐藏金额、查看二级分类、切换正常 / 超支预算、同步失败及后台导入状态。
- 主题与尺寸切换后，对新增 DOM 继续套用同一配色，不丢失图标家族色。
- 仅新增本目录下 HTML / CSS / JS / 本说明，未修改主 demo、共享样式、Flutter 或资源索引。iframe 读取当前 demo，因此能跟随主线已确认的布局更新。
- 唯一预览容器适配：数据管理原导出稿默认生成长页，在 iframe 内固定为所选手机高度，并让内容区域滚动，保证附件末尾可达；不修改其内容布局。
- 本地服务器是必要条件。若服务器未运行，可在 `docs/design/card-refresh` 执行 `python3 -m http.server 8374 --bind 127.0.0.1`。

## 本地验证

使用本地 Chrome（Playwright `channel: chrome`），已验证：

- 6 页 × 2 主题 × 2 外观 × 3 尺寸，共 **72 个组合**：手机尺寸正确，无横向溢出，无页面脚本错误。
- 12 张代表截图：六页浅色标准屏、六页深色青莲紫小屏；另检查浅深整页、手机宽度页面、账户列表和附件底部截图。
- 375px 浏览器下评审页无横向溢出，六页选择可达。
- 主页面金额前后计算色完全相同：默认浅色支出 `rgb(37, 133, 109)`、收入 `rgb(189, 93, 80)`；深色沿用原浅绿 / 浅红。
- 金额隐私开关、账本弹窗、餐饮二级分类弹窗可操作；重绘后图标颜色保留。
- 超支示例剩余金额保留原错误色 `rgb(179, 38, 30)`。
- 自定义图片均未收到家族色属性；账户图片解除灰度后保留原 SVG 内容。
- 320×568 数据管理能滚动到“导入附件”末项，未被 iframe 裁掉。

截图及 JSON 结果仅保存在本地 `qa/color-balance-review/`，不提交。以上证明 HTML 提案的交互与布局，不代表全 App 配色已确认或原生验收通过。
