# AI Eval v1

固定账本、固定日期和独立标准答案，用于重跑助手查询、记录失败样例，以及比较模型或代码改动。通用执行、断言和报告能力在纯 Dart 的 `packages/agentcore`；账本数据、业务标准答案、App 适配器留在 BeeCount。

## 两种模式

| 模式 | 实际执行 | 能证明什么 |
| --- | --- | --- |
| 离线（默认） | 用例给定工具参数 → 真实 Facade、工具选择/校验、授权、SQLite 执行 | 工具是否可用，范围、币种、数值和边界是否正确；不是 LLM 理解准确率 |
| 在线 `--live` | 自然语言 → 实际服务商模型 → 同一 App 执行链路 | 模型能否选择工具、生成正确参数、使用上下文并给出包含预期数值的答案 |

在线模型看不到 `oracleCalls` 或标准答案。3 个追问用例把前一轮真实回答带入下一轮。每个用例重新创建内存数据库，固定时间为 `2026-09-30 12:00:00 Asia/Shanghai`；不会启动模拟器、读取用户账本或修改 App 配置。在线请求只发送合成样本，但会消耗服务商额度。

## 运行

在仓库根目录执行，需 Flutter 3.27.3 / Dart 3.6 和已安装依赖：

```bash
flutter pub get
dart run tool/ai_eval.dart
dart run tool/ai_eval.dart --filter followup --output build/ai-eval/followup
```

在线模式使用环境变量，不在仓库或命令参数中保存 Key：

```bash
export AI_EVAL_BASE_URL='https://your-provider.example/v1'
export AI_EVAL_MODEL='your-tool-calling-model'
# 使用本机安全方式设置 AI_EVAL_API_KEY，避免把真实 Key 写进命令历史。
dart run tool/ai_eval.dart --live --filter overview-current-1
dart run tool/ai_eval.dart --live --output build/ai-eval/my-model-v1
```

`--filter` 匹配用例 ID 子串或完整 tag；空匹配报错，不会被记为成功。`--output` 为文件前缀，生成 JSON 和 Markdown。默认目录为 `build/ai-eval/`，不提交报告或凭证。全部通过退出 0；断言失败退出非 0；CLI 参数或配置错误退出 2。失败用例也会写入报告，随后以失败状态退出。

独立运行通用包测试：

```bash
cd packages/agentcore
dart test
```

## 数据集与标准答案

- `fixtures/ledger_v1.json`：65 笔合成交易、3 个账本、父子分类、CNY/USD 账户，显式指定折算金额，避免实时汇率依赖。
- `fixtures/readonly_cases_v1.json`：77 个用例、82 轮对话；原 63 例保持不变（原始 57 例及 6 条简单入口题），追加六类分析模板的中英文用例（`analysis-template`，12 例）和实际推荐追问的中英文两轮用例（`contextual-followup`，2 例）。包含收支概览、按月分类趋势、同比/环比、占比、明细、空月份、跨年、统计排除、转账、普通收入式退款、自定义月起始日和账本隔离。
- 金额标准答案独立手工核算，不通过生产查询函数生成。主账本 9 月支出 1295、收入 5020、结余 3725；全年支出 9225、收入 9020、结余 -205。
- 餐饮 2026 年各月支出为 `[100,150,0,80,200,0,100,300,120,0,0,0]`，合计 1050。住房合计 8000。USD 交通支出 10 的账本折算额为 72，交通合计 117。
- 9 月一级分类金额依次为住房 1000、餐饮 120、交通 117、购物 53、未分类 5。排除统计的 99999、转账 500、另一账本的 888888 不应进入统计。
- 月起始日为 15 的账本，本月区间为 `[9月15日,10月15日)`，支出 50；边界外交易不计入。
- 明细上限用例断言当前工具默认分页契约（20 条），不是让模型通过读取有限明细计算汇总。
- 推荐提问与 App 中完整问题文本逐字一致，由服务入口回归测试防止文案与 Eval 漂移。最近六个月含当前月：4—9 月支出依次为 1080、1200、1000、1100、1300、1295，合计 6975；一级分类不与明细分类混合。

定向运行完整模板：`dart run tool/ai_eval.dart --filter analysis-template`；推荐追问：`dart run tool/ai_eval.dart --filter contextual-followup`。`entry-prompt` 保留此前三条简单问题的历史回归，不再代表当前六类模板目录。页面/服务测试逐字关联当前中英文模板与 Eval，另覆盖完整问题持久化、工具审计、硬只读策略、拒绝授权、不支持工具模型的提示，以及最新回答追问的点击、恢复和账本隔离；这些确定性测试不计入在线模型准确率。

业务契约或统计口径变更时增加 fixture/case 版本，并说明变更原因；不要只为让某个模型过关而改标准答案。新增 case 应同时填写输入、工具结果和可检查的答案事实。

## 报告与断言

JSON 包含用例明细、实际工具参数/结果、回答、失败字段路径、分 tag/分断言通过率、模型回合数、工具调用数、权限拒绝次数、执行前校验未通过次数（`rejectedCalls`）、实际 HTTP 请求总数、用例总耗时 p50/p95。记录 fixture/assertion 版本、模型、时区、代码 revision 和 dirty 状态。校验未通过不是权限拒绝，也不是一次实际执行；模型的纠正仍计入模型回合数。

`numeric_and_scope` 对必需工具结果进行对象子集匹配；数组要求长度/顺序完全一致，数值绝对容差 `1e-9`。显式检查币种、起止时间、月度点、比较金额和统计口径，不只比较总额。额外调用的工具必须执行成功；只读策略拒绝记账和记忆写入，并检查交易数量未变及无拒绝调用。

App 不再根据关键词匹配的工具名拦截最终回答；缺少目录匹配工具仅写诊断日志。Eval 仍检查各用例要求的真实数据与工具结果，不因此放宽标准答案。查询参数校验、有限纠正、真实执行错误和权限策略保持独立；未纠正的已知参数错误仍返回 `agent_query_validation_failed`，不再与工具选择混为一谈。

断言版本 2 追加可选 `grounded_followups`：检查两轮用例第一轮实际生成的追问包含标准问题（实际日期边界、结束时间不包含及分类层级），第二轮仍检查真实工具金额与范围。原题的数值/范围断言未放宽。报告也记录实际推荐项；不额外调用模型生成推荐。

用户明确要求不比较/同比/环比时断言比较字段；只要求列出金额的用例不限定未请求的比较字段，但全部月度金额和范围仍必须正确。负金额允许 `-205`、`-¥205` 等格式，避免把货币排版误认为数值错误。不存在分类使用明确的虚构名称「太空旅行」，不使用容易被理解为“未分类”的描述。

`answer_facts` 仅检查回答中预期数字出现、非空；`clean_answer` 检查部分实现异常和协议泄露。它们不等于完整语义正确性：数字出现在错误月份、单位不对、错误解释或空数据场景编造内容仍可能漏检。上线验收还需人工抽检；后续可扩展结构化答案断言，不能仅依赖 LLM 自评。

每次在线运行都可能波动；比较时应固定数据集、断言版本、服务商、模型与参数，对同一命令重复运行。分别用不同 `--output` 留存报告比较，不覆盖基线。当前不自动执行 LLM judge，不宣称一次通过即稳定达标；暂不统计首字延迟/token（上游未统一输出 usage）。

## CI 与范围

`.github/workflows/ai-eval.yml` 在相关 PR/main 改动及手动触发时运行通用包测试和离线回归，并上传报告。不注入线上凭证，不产生模型费用；在线评测需显式在本机运行。

v1 聚焦只读统计；完整模板覆盖预算规划所需的只读统计，但没有评估预算建议本身的财务合理性。尚未覆盖歧义澄清、真实关联退款净额、拆分/周期交易、预算使用率与写入、写操作预览/幂等/撤销、无 tool-call 模型和错误配置；后两项继续由现有能力/协议单测保障，不能把本数据集成绩外推到这些能力。
